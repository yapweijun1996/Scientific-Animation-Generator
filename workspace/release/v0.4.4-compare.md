## Structural improvements

- Dedicated standalone entry, bootstrap, UI and types.
- Shared runtime dependency injection for Worker and texture sources.
- Generated runtime version validation.
- `standalone-export.ts` reduced to export orchestration.
- Main HTML export and ZIP export share one runtime generator.
- Browser QA added as a repeatable project test.
- Planet texture binaries are now explicit source-workspace build inputs.

## Publication-package repair

The first v0.4.4 HTTPS inspection detected three Earth texture 404 responses. This exposed that the newly bound source workspace did not contain the binary planet assets, although they remained available in the prior project store.

The issue was repaired before final release by restoring the verified files, synchronizing all planet maps into `public/assets/planets/`, adding exact production asset checks and adding HTTP status gates to browser QA. The application was then rebuilt and the full browser/export/offline matrix was rerun successfully with zero HTTP errors.

## Risk assessment

- The final standalone HTML is approximately 7.9 MB because it contains the complete Three.js runtime and real planet maps required for a zero-dependency offline file.
- Firefox headless used Canvas fallback because WebGL was unavailable in that test environment; this verifies the designed compatibility path.
- No database, account, cloud, analytics or personal-data behavior is involved.

## Decision
