# v0.6.0 Engineering Memory — Scientific Learning & Observation

## Release objective

Add scientific learning, astronomical event exploration and observer tools without regressing the v0.5 mobile-time foundation, offline PWA, standalone HTML, ZIP export, WebGL or Canvas fallback.

## Durable decisions

### Calculation and presentation are separate

Scientific position state is produced by the installed astronomy provider. Learning Scale, Real Distance, Real Scale, body visibility, atmosphere, lighting, locator labels and camera framing are presentation concerns. Presentation must not mutate calculated state.

### Principal Moon phases use ecliptic longitude difference

New Moon, First Quarter, Full Moon and Last Quarter are defined by Moon–Sun geocentric ecliptic longitude differences of 0°, 90°, 180° and 270°. True 3D elongation remains a separate display measurement because lunar ecliptic latitude means it need not equal exact 0° or 180°.

### Real Distance requires a complete safety policy

Linear AU spacing alone is not enough. The mode must also provide:

- body-size safety bounds;
- a dedicated Earth–Moon envelope;
- camera fitting from the outermost aphelion and current aspect ratio;
- full-system Focus Sun semantics;
- locator labels for small objects;
- WebGL and Canvas parity;
- deterministic QA diagnostics for frustum inclusion and overlap.

A field-test screenshot exposed the failure mode: real distances combined with teaching-scale bodies and a compressed-mode camera made inner objects appear inside the Sun and cropped outer planets.

### Legacy snapshots must be migrated explicitly

v0.5 snapshots did not contain the v0.6 `scaleMode`. When the old `visualMode` is scientific, migrate it to `real-distance`; otherwise use `learning`. Do not depend only on default parameter merging.

### Scientific claims require classification

Use exactly these public labels:

- Calculated
- Dataset verified
- Educational approximation
- Visual enhancement
- Outside verified range

Do not use Dataset verified unless an identified external reference dataset, comparison method and absolute residual are present.

### Eclipse guard

Eclipse events are educational node-proximity geometry candidates. They must remain marked `localCircumstancesAuthoritative=false` and must never be described as authoritative local eclipse-contact predictions.

### Browser storage is untrusted input

Values read from localStorage must be schema-validated, bounded and escaped before HTML insertion. v0.6 added a malicious custom time-preset fixture to Chromium, Firefox and WebKit interaction tests.

### Release lifecycle

1. Lint and typecheck.
2. Production build with exact source/dist asset checks.
3. Domain, architecture, export and scientific tests.
4. Full 17-shard browser matrix.
5. PWA, accessibility, privacy, security, licence and attribution review.
6. Write release, accuracy, compare and rollback documents.
7. Create and verify a pre-publish recovery point.
8. Publish only the generated `dist` package.
9. Inspect the actual stable HTTPS URL and every runtime asset.
10. Run published accessibility and Lighthouse audits.
11. Create and verify a post-publish recovery point.
12. Bind evidence, close the task and update KB-MCP.
