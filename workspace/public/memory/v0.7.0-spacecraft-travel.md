# v0.7.0 Spacecraft Travel — Project Memory

## Durable architecture decisions

- Travel uses a shared `TrajectoryEngine` and `MissionStateMachine`; UI and renderers do not own mission mathematics.
- Earth is the origin for every v0.7 mission.
- Hohmann is the only installed interplanetary trajectory model.
- Direct and Gravity Assist are fail-closed until dedicated scientific solvers are installed.
- The same `MissionSnapshot` drives the editor, WebGL, Canvas, IndexedDB, standalone HTML and ZIP export.
- Travel resources are lazily created only after a mission is planned or restored.
- Runtime mission state is authoritative for saving camera/active state.
- Project saves are serialized to preserve request order.
- Mission dashboard rendering is visibility-aware, throttled and includes a trailing refresh.
- Simulation time remains the authority for mission progress and event crossing.

## Scientific boundaries

- Travel is educational, not operational.
- Hohmann transfer uses an idealised heliocentric two-body model.
- Delta-v is an impulsive educational budget.
- No launch vehicle, atmosphere, mass/staging, thermal, power, communication, radiation or instrument systems are included.
- No external mission dataset is bundled; no Dataset verified claim is made.
