# v0.7.0 Rollback Plan

Release status: **candidate; not yet published**

## Current safe baseline

The stable public URL currently serves verified v0.6.0.

Verified v0.6 recovery point:

- `backup_2206707b-dc7_ms7fomwl`

Older v0.5 recovery point:

- `backup_2206707b-dc7_ms6ih89w`

## Pre-publish rule

Do not overwrite the stable URL unless:

1. lint, typecheck and production build pass;
2. domain and export smoke pass;
3. PWA/compliance/privacy review is recorded;
4. one clean consolidated browser matrix passes;
5. a candidate recovery point is created and verified.

## Rollback triggers after publication

Rollback immediately if post-publish verification finds:

- application version is not v0.7.0;
- any required JS, Worker, texture, manifest or service-worker file returns 4xx/5xx;
- Explore or Learn no longer starts;
- Travel cannot plan or start a valid Mars mission;
- mission snapshots cannot restore;
- WebGL falls back unexpectedly where WebGL is available;
- Canvas fallback fails;
- standalone HTML requires network access;
- console/page/request errors appear in required browser checks;
- offline cached reload fails.

## Rollback procedure

1. Stop further v0.7 publication or documentation updates.
2. Restore the verified v0.6 recovery point `backup_2206707b-dc7_ms7fomwl` to the project.
3. Republish the restored v0.6 `dist` to the same stable URL.
4. Verify the main page shows v0.6.0.
5. Verify main JS, CSS, Worker, service worker and representative planet textures return HTTP 200.
6. Verify desktop and mobile startup, Learn mode, Real Distance and offline behaviour.
7. Record the failed v0.7 release as rolled back and keep `task_010` open.

## Data compatibility

v0.7 adds optional mission state. A rollback to v0.6 ignores unknown mission fields at the application level and does not require server-side data migration because project state is local IndexedDB / exported JSON.

Users should retain downloaded `.scienceproject` files created in v0.7. Re-import into v0.7 after the issue is corrected; v0.6 is not expected to present Travel controls.

## Recovery-point rule after successful publication

After v0.7 is published and fully verified, create and verify a new v0.7 recovery point. Do not label the current workspace candidate backup as the final online recovery point before the stable URL itself has been checked.
