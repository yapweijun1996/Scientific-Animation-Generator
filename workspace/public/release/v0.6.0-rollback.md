## Rollback triggers

Rollback immediately when the published v0.6.0 package shows any of the following and an immediate forward fix is not safer:

- Stable URL does not load or does not identify v0.6.0.
- Required JavaScript, CSS, Worker, planet texture, manifest, service worker or icon returns HTTP 4xx/5xx.
- WebGL primary runtime fails where WebGL is available and Canvas fallback does not recover.
- Mobile full-canvas controls become inaccessible.
- Offline reload, standalone HTML or ZIP export is broken.
- Simulation time becomes non-deterministic or reverse time mutates state incorrectly.
- Real Distance places visible body envelopes inside each other or crops the outer system.
- Published accessibility or Lighthouse review exposes a release-blocking regression.
- Scientific phase/event output contradicts the documented installed model.
- Privacy, security or attribution files are absent from the production package.

## Preferred rollback procedure

1. Confirm the current stable URL issue and preserve screenshots, console output, failed request list and affected browser/viewport.
2. Use `restore_project_backup` with backup `backup_2206707b-dc7_ms6ih89w`, project ID `project_2206707b-dc70-4db8-be41-19c2b1020d52`, mode `replace`, and explicit confirmation.
3. Verify the restored recovery point before publication.
4. Republish the restored v0.5.0 distribution to the same stable URL.
5. Verify over HTTPS:
   - page loads and displays v0.5.0;
   - desktop, tablet and mobile render;
   - all runtime assets return HTTP success;
   - service worker and manifest are available;
   - standalone HTML and ZIP export work;
   - offline reload works.
6. Record the rollback reason, evidence and recovery time in task_009 and the project knowledge base.
7. Keep task_009 open until a corrected v0.6.x candidate passes all release gates again.

## Partial recovery

A single file may be restored with `recover_deleted_project_file` only when the exact missing or corrupted file is known and the rest of the package is proven unchanged. A full replace is preferred for an unknown production regression.

## Forward-fix rule

Do not patch the published distribution manually. Fix the source workspace, regenerate standalone runtime, rebuild, run the complete matrix, create and verify a new recovery point, then republish.
